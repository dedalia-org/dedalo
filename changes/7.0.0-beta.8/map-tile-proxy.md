**Action needed: check which machine reaches which tile provider.** The geolocation map no longer asks a source stored in a record, an ontology default or (on most installations) OpenStreetMap for its tiles from the browser. It asks the installation's own server (`/dedalo/core/api/v1/map_tile`), which checks that the person may read the field, finds the source the request names, fetches the tile and hands it on. So **the server** needs outbound HTTPS (port 443) to `www.ign.es`, to whatever host a stored source or an ontology default names (port 80 for an `http` one) and — on an installation with a public address (`DEDALO_HOST`) — to `tile.openstreetmap.org`. An installation **without** a public address does not relay OpenStreetMap (its policy forbids relaying it under the shared identity such an installation has, see below): there the server never asks OpenStreetMap, and **the viewers' browsers** still need to reach `tile.openstreetmap.org`, as before. An installation whose server has no outbound access (a firewalled network, a DMZ without egress) shows **blank** stored, default and IGN layers after this update, and a blank OpenStreetMap base map too if it has a public address, until the server is allowed to reach those hosts. Check it before updating.

A request names a source (a built-in one, one stored in the record or one of the field's ontology defaults) and never carries an address, so an editor can no longer make a page load an image from wherever they typed, and a map drawn from these tiles can be exported to an image without the browser refusing it. Only the people who can read a geolocation field get its tiles, and only the record's scope; the tile is a private, `nosniff` image served under a sandbox policy. A tile of a stored source or an ontology default is kept by a browser for at most five minutes (an edit of the source keeps its address, so a longer time would show the old tile after the edit); a built-in's for at most a day.

The server fetches politely: at most four requests at a time to one provider, the provider's own caching headers followed (a small memory, bounded in bytes and in entries, answers repeats), no robots.txt and no prefetching because a person is looking at the tile, and the same tile asked by several people at once is fetched once. One person cannot use a provider up: past a burst of 400 provider calls (a 4K display with two layers asks for 320 tiles at once) they are held to five a second, and a tile already in the memory costs nothing; a tile abandoned while it waited for its place (the viewer zoomed or panned on) was never sent and is not counted. One person's view cannot be everyone's line either: at a provider everybody shares (OpenStreetMap) they hold four places in its queue and the rest of their tiles wait in a line of their own, so another person's tile is served after one turnover; their slow stored hosts hold three of the eight places that stored sources share, never all of them. When the server cannot take a tile in time the tile is refused as busy (`429` with a `Retry-After`, counted in `map_tile_busy`, not a provider failure) and the page asks again, twice. OpenStreetMap's tile policy generally does not recommend a caching proxy, and permits one that identifies the service: the server's `User-Agent` names **this installation** as the contact — `dedalo/<release> (+<its public address>)` — when it has a public address an outside machine could reach (`DEDALO_PROTOCOL` + `DEDALO_HOST`, used only when it is a clean `http://` or `https://` `host[:port]` — an international name is sent in its ASCII form), and the same address, followed by `/`, is sent as `Referer`, as the policy asks: the two are always sent together and name the same origin, or not at all. An installation reachable only from its own network, or whose `DEDALO_HOST` carries anything but a host and port (credentials, a path such as `/dedalo`, a query), has only the shared `dedalo/<release> (+https://dedalo.dev; heritage cataloguing)` identity (an internal name published to a third party is a map of the network) — the generic proxy identity OpenStreetMap's policy forbids — so it **does not relay OpenStreetMap**: its viewers' browsers load the OpenStreetMap base map straight from `tile.openstreetmap.org`, as before this change (the page's `img-src` admits that one exact host for it; such a map's image export is tainted, and OpenStreetMap sees the viewer's address), and a server request for an OpenStreetMap tile — a stored source or an ontology default on its host included — is refused (`503`, counted in `map_tile_identity_withheld`). The IGN overlay is still relayed, under the shared identity and with no `Referer`. `DEDALO_HOST` is optional: to have OpenStreetMap relayed, set it to the public name and, for a site served over TLS, `DEDALO_PROTOCOL=https://` (the default is `http://`). A tile that came with an `ETag` or `Last-Modified` is, once expired, asked about with `If-None-Match` / `If-Modified-Since` (a `304` costs the provider a header), as the policy asks of a cache.

Anything the provider answers that is not a png, jpeg, gif or webp image of the right kind (an error page, an SVG), or whose header declares an enormous size (an image that decodes to gigapixels), is refused, and a failure is one "the external source could not be reached" refusal that names no host. A provider that simply has no tile for a place (a 404, an empty answer) is not an error: it is a blank tile, the browser is told it may remember that for two minutes (the server keeps nothing of it, and the call is charged like any other), and nothing is logged for it. When a provider is down the log says so once a minute per source, not once per tile. Two built-in sources exist: `osm` (OpenStreetMap) and `ign_admin_units` (the IGN's administrative units, CC BY 4.0).

A map source must now use the standard web port of its scheme (80 or 443): the server reaches no other, and a source on `:8080` used to save and then never draw. A WMS source whose CRS is geographic (`EPSG:4326`, `EPSG:4258`) is drawn from zoom 8 up: the picture such a service returns is only registered with the map to under a pixel from there. An ontology default now shows its attribution on the map and keeps to its own zoom bounds, and its label is plain text (a label with `<` or `>` is rejected).

The page's `img-src` policy no longer names `*.tile.openstreetmap.org`, `*.tile.osm.org` or `*.basemaps.cartocdn.com` (it names the one exact `tile.openstreetmap.org`, for the direct path above). The ArcGIS, DARE and Google base maps of the `ARCGIS`, `NUMISDATA`, `VARIOUS` and `GOOGLE` geolocation providers are not relayed (their terms do not allow it, or are not confirmed) and still load directly, so `server.arcgisonline.com` and `dh.gu.se` stay. Stored and default sources appear in the map's layer control, switched off until the viewer turns them on. See [the tile proxy](./core/system/map_tile_proxy.md).
