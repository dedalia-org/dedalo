# Dédalo v7 observers / `set_dato_external` (rebuilt 2026-08-02)

When an observed component is written, its declared observers recompute. Since CLOSURE_PLAN Step 2 (2026-10-01, `WC-2026-09-30-record-write-obligation-ledger`) NO door calls `propagateToObservers` itself: every record write ends in `afterRecordWrite` (`src/core/section_record/record_write.ts`), which REQUIRES an `observed` declaration (`keys` with per-key before/after, `replace`, `birth`, `death`, `recompute`, `cascade-owned`, or `none` with a reason — a missing one is a typed refusal naming the door) and enqueues ONE entry on the OBLIGATION LEDGER (`src/core/section_record/obligation_ledger.ts`): `saved` = the value after, `removed` = `removedLocators(before, after)` (the ONE removed-set rule). The ledger drains on the COMMIT-ONLY lane (`registerCommitAction`; inline with no transaction), so the save, the TM component restore and whole-record restore, both undelete doors, the bulk revert, create, duplicate, delete, the portal unlink, the data wipe and a CSV import row all propagate after COMMIT. The tree-move writers (`relations/parent.ts`) and the archive restore (`observed: none`, PENDING) are the enumerated exceptions in `write_obligations_tripwire`. The bulk doors that bypass every cascade (portalize, v6→v7 migration) are healed by `scripts/observer_reconcile.ts`.

Three files, one law each: **`observer_subscriptions.ts` = WHICH edges exist**, **`observers.ts` = the dispatch + recompute KERNEL and the safety laws**, **`observer_reconcile.ts` = replaying the same recompute offline** — plus the law registry **`external_laws/`** (WHAT a mirror derives: `classify.ts` the ONE classifier, `merge.ts` the ONE merge, `resolvers.ts` the ONE target table + host predicate, one file per law) and the read door **`external_refresh.ts`** (the update-external button). There is no fourth copy of discovery — the reconciler used to have one.

## THE HEADLINE: discovery is REVERSE, observer-declared

An edge dispatches **iff the OBSERVER declares it in `properties.observe` with a `server` block**. The observed component declares NOTHING. Standard observer semantics: the subscriber registers itself. No code activation table, no config switch — the ontology decides, and the per-edge kill switch is an ontology edit (blank that entry's `server` key).

Discovery used to be FORWARD-ONLY (read the saved node's `properties.observers`), so an edge had to be declared TWICE and any half-declared edge was silent dead config. That is why `rsc19 -> oh28` never fired: oh28 declared `observe` correctly, rsc19 never declared the forward mirror.

Registry: `src/core/section/record/observer_subscriptions.ts` — built over the WHOLE ontology (`getNodesWithProperty('observers') ∪ getNodesWithProperty('observe')`). `buildSubscriptionIndex` (pure, gate-driven), `validateSubscriptionContract`, `getSubscriptionRegistry`, dispatch lookup `getObserverSubscriptions`. Cached through `createOntologyCache` — the invalidation hub clears it after EVERY dd_ontology write (deferred to COMMIT), so registration is by construction and the module-level cache is legal; `clearObserverSubscriptionRegistry` for out-of-band ontology surgery. Warmed + loud-validated at boot in `src/server.ts` `startServer` (the probe also registers the `observers_registry` ops gauge). Two races closed on top: a build TOKEN planted before the reads (a concurrent dd_ontology COMMIT ⇒ serve the index, do not cache it) and an in-tx memo (`getTransactionMemo` — S1-14 forbids seeding a shared cache from an ambient tx; one build per tx span). The index is deep-frozen and its Maps runtime-hardened (mutators shadowed to throw) — **rebuild on invalidation, never patch**.

**The ONE dispatchability predicate is `entryServerBlock(entry)`**: undefined for an absent `server` (client-only observer) AND for a present-but-non-object value (`server:null` — flagged RED, never dispatched, never thrown on). Match law: the FIRST `observe` entry, in array order, whose `component_tipo` equals the observed tipo or is `'all'`. Client-only is NOT the majority: measured 2026-08-02 on a production install's ontology, 76 of 136 `observe` entries carry a `server` half (39 of the 67 nodes with `observe`); the suite DB was 73 of 126. Re-measure with the recipe below, don't quote these.

Measured on a production install's ontology (2026-08-02, rebuild the numbers with the recipe below): 80 registry rows, 75 dispatchable, **73 distinct edge keys = 64 mirrored + 9 reverse-only that had NEVER dispatched**; 0 dead wildcards, 0 unresolved hosts, 0 cycles; 4 forward-only specs (`rsc1139`/`rsc1140`/`rsc1401`/`rsc1403` -> `rsc19`) that have been dead config for this install's whole life and are now reported LOUDLY at every boot. The 9: `oh93->oh28`, `rsc19->oh28`, `rsc860->oh87`, `numisdata282->numisdata321`, `numisdata1373->numisdata1478`, `numisdata1373->numisdata1479` do real work; `rsc30->rsc1369`, `rsc36->rsc860`, `rsc36->rsc1368` land on the TERMINAL NO-OP branch (don't sell those three as recovered behaviour).

## The forward `observers` array is LEGACY — exactly two residual jobs

1. **Compiling the `'all'` wildcard.** An `observe` entry with `component_tipo:'all'` is a MATCHING RULE with no intrinsic scope; without the forward specs bounding it, it would mean "every save in the system". The builder compiles it to exactly the forward-declared edge set in pass 1 only (production example: `numisdata282->numisdata250`, `numisdata1451->numisdata257`, `tch555->tch557`); pass 2 `continue`s on `'all'`, so a wildcard can NEVER mint an edge without a forward spec. A wildcard nobody forward-declares admits ZERO edges ⇒ `deadWildcards`, RED.
2. **Host targeting for a REUSED component.** A component declared once and reused across sections needs the forward spec's `section_tipo` (production example: `rsc387` declares observer `hierarchy93` three times, `section_tipo` on1/ts1/dc1, while hierarchy93's own ontology position is section hierarchy20 — 9 of the 64 mirrored edges are this shape). Never silently retarget these to the observer's own section.

**Pass 3 — edges DERIVED from a law** (2026-10-30, WC-2026-10-30-observer-law-derived-edges): for each covered node, `externalLawDependencies(resolveExternalLaw(node))` — ONLY `source_overwrite` yields one, `{observed: data_from_field, via: pointer}` — becomes an edge `declaration:'law-derived'`, `origin:'law'`, `via`, entry `{server:{config:{use_inverse_relations:true}, perform:{function:'set_dato_external'}}}`, host = the observer's own section. A DECLARED key (any pass-1 spec, any observe entry with a string `component_tipo`, client-only included) WINS ⇒ `diagnostics.lawShadowed`, no derived edge — a client-only entry is the per-edge kill switch. Derived edges are in the cycle scan, exempt from the observe-entry contract checks, seen by `isObservedTipo` and the hop leaf pre-gate for free. Live: `numisdata77 → numisdata679` derived (via numisdata656), `numisdata11 → numisdata965` shadowed.

A forward spec with no matching `observe` entry = `forwardOnly` diagnostic = dead config, RED. Fix the ONTOLOGY (add the observe half, or delete the spec) — never pin it in code.

## Host-section resolution — "which records do I recompute?"

`resolveHostSection` (`observer_subscriptions.ts`), in order:

1. the `observe` entry's own `section_tipo` — the authoring home for new edges (nothing ships it yet);
2. a forward spec's `section_tipo` (reused-component targeting; the literal `'self'` falls through);
3. the observer's OWN section (`getAncestorSectionTipo`), refined by the SQO filter path with **virtual↔real equivalence** — a virtual section's `relations[0].tipo` names its real section (numisdata5 ≡ numisdata276; on1/ts1/dc1/cont1/cult1/es1 are all virtual sections of hierarchy20; helper `getSectionRealTipo`). The PATH's face wins, because stored records carry the virtual tipo. A NON-equivalent path section resolves to nothing — never a silent retarget;
4. unresolved ⇒ LOUD refusal naming the edge (`observers_host_section_unresolved`; validator `hostUnresolved` RED). Nothing hits this today.

Only the **SQO-filter** shape needs a host at dispatch. Observable-driven resolvers (`use_observable_dato`) take their targets from the SAVED LOCATORS and never search by section at all.

## Dispatch: branch order in `propagateToObservers` (read it as a decision list)

`server === undefined` ⇒ skip. Then, in this order:

1. **info observer** — observer model is `component_info` or an alias of it (`component_state`, `component_calculation`) AND no `perform`. Targets: `server.filter` is an SQO object ⇒ search the HOST section, every clause's `q` := the saved record's locator, `from_component_tipo` from the FIRST clause's last path step, `sqo.limit = 'all'`; `filter:false` ⇒ the saved record itself. Per target: recompute the widgets, write ONE `matrix_time_machine` row (lg-nolan) and **deliberately never touch the live misc column** (stored misc is legacy, live reads compute). Same-record targets ride the save response as `observersData`. `recomputeInfoObserver`.
2. **`filter:false`, no perform, non-info** — the written-out TERMINAL NO-OP (ported as PHP's behaviour for the hi family). Distinct from `filter` ABSENT; the two shapes used to be indistinguishable here.
3. **relay** — no `perform`, `filter` ABSENT, `use_observable_dato`, observer not info. A pure TRIGGER: read the observer's value "with references" and re-enter propagation as if it had just saved. **WRITES NOTHING** — no value change, no TM row, no dd197/dd201 stamps (`runObserverCascadeHop`; divergence WC-2026-08-02-observer-relay-writes-nothing).
4. **`set_dato_external`** — `classifyObserverServerShape(server)` (`external_laws/resolvers.ts`, PHP's closed config switch, WC-2026-10-30-observer-target-resolvers): `use_observable_dato`+`use_self_section:true` ⇒ `self_and_observable`; `…:false` ⇒ `observable`; `use_inverse_relations:true` ⇒ `inverse` (`findInverseReferences` of the saved record THROUGH THE LAW'S POINTER, host-filtered per row, deduped, lock-sorted); anything else, no config included ⇒ `self`. Then `getExternalLaw` (refused ⇒ `reportRefusedLaw` ONCE per edge per save, no targets) and `resolveObserverTargets` → `recomputeMirrorAndHop('on-write')`. Any other perform ⇒ counted `observers_server_shape_not_covered`; **`refresh_data` (rsc1214) is a NAMED exemption** (`SERVER_SHAPE_EXEMPTIONS`). An SQO filter next to `self`/`self_and_observable` is refused (`filter_not_covered`).

So the WIRED resolver kinds are **self** (info + `filter:false` — the saved record), **observable** (`use_self_section:false` + `use_observable_dato` — the saved data's target locators), **self+observable** (both true — the union), and **sqo_filter** (info + object filter — a search over the host section). `'all'` is a matching rule compiled at registry build, NOT a resolver. The `set_dato_external` resolvers are the four of step 4 — `use_inverse_relations` is typed in `ObserveEntry.server.config` and WIRED since 2026-10-30 (numisdata965 ← numisdata11), and the six no-config legend-symbol edges (numisdata563/574/575/993/1227/1229) are the `self` resolver.

### Law (c) — inverse search

The observer's data := every record referencing the target through `properties.source.component_to_search` — **or any EQUIVALENT of the target** reachable through `properties.source.data_from_field` — restricted to `source.section_to_search`. Existing entries keep their stored order; new references append with `nextObserverItemId` (a non-finite legacy id must never NaN-poison the max, or every appended entry serializes id `null` and breaks id-based pairing downstream). New entry shape: `{id, type:'dd151', section_id:int, section_tipo, from_component_tipo:observerTipo}` — int-canonical since WC-2026-08-10-section-id-int-canonical (`canonicalizeStoredSectionId`; pre-sweep stored entries may still carry strings, and the dedup keys normalize both forms). Search is uncapped, ordered `section_tipo, section_id`.

**The seed** — `collectExternalSeed` (async half) over `buildExternalSeed` (pure half): the target record PLUS each `data_from_field` peer's bag "with references" AT THE TARGET = the peer's stored bag ∪ its typeRel-gated closure (`relations/related.ts` `getStoredWithReferences` — dd620 nothing, dd467 one inverse hop, dd621 the FULL symmetric transitive closure, both recursion directions, memoized; typeRel is read from `properties.config_relation.relation_type_rel`, defaulting to dd620). Every seed entry is re-stamped `from_component_tipo = component_to_search` — the search must match the REFERENCING component's locators, never the peer's own stamp. Semantics: **the mirror lists records referencing this record OR ANY OF ITS EQUIVALENTS.** The dispatch is polymorphic: only a `component_relation_related` peer computes the closure; any other model gets the stored bag even with dd621 in its config.

**Why one hop is wrong — measured** (19,908 numisdata3 records holding numisdata77, against the values migrated from the previous engine):

| seed | exact | locators lost |
|---|---|---|
| self only | 7,430 | 318,122 |
| self + peer stored bag (ONE hop) | 11,953 | 247,933 |
| self + dd621 transitive closure | 19,885 | 13 |

The closure IS the law. Do not weaken `getStoredWithReferences` to the stored bag "for performance".

**THE TARGET LAW — both halves of the change, and the whole class** (2026-08-06). `propagateToObservers` takes an **`ObservedChange` `{saved, removed}`**, `removed` REQUIRED (a trailing optional would have defaulted to the bug; every door must state `[]` explicitly, and a static gate scans for call sites that don't). Removed locators join the target set in the **external** and **relay** branches, NOT the info branch. Then, when the OBSERVED tipo is one of the observer's own `data_from_field` peers AND is `component_relation_related` with dd467/dd621, the target set expands to the equivalence-class closure:

```
targets = closure(saved) ∪ ⋃ closure(r) for r ∈ removed        # then SORTED by (section_tipo, section_id)
```

Complete in BOTH directions with no branching — on a split, any affected node is either still connected to the saved record or sits behind the first removed edge on its path; on a merge, `closure(saved)` is already the merged class. Guarded cheapest-test-first (`data_from_field` membership before any node/model resolution), so a non-equivalence edge like `hierarchy93 ← rsc387` pays NOTHING. **The sort is not cosmetic**: each recompute takes a `FOR UPDATE` lock and `withTransaction` JOINS an ambient tx, so class expansion + unordered acquisition = deadlock between concurrent imports. A class > 50 is counted (`observers_equivalence_class_wide`), never refused.

Why it matters: dd621 is TRANSITIVE, so one edge change re-partitions a whole group — in A—B—C, changing B—C changes A's group too. A 2-member group hides this, which is why the gap survived (the reported numisdata36 case looked fine on ADD). Gate: `test/unit/observer_equivalence_native.test.ts` (asymmetric 3-chain, split AND merge, driven through `saveComponentData` — a direct `propagateToObservers` call would bypass the pre-save snapshot and pass vacuously).

**The removed set is computed at the chokepoint** (`save_component.ts`): `preSaveItems` snapshots the FULL relation slot under the lock BEFORE the dataframe narrowing; the diff keys on `(section_tipo, section_id)` — **never on item id**, because an `update` that retargets a locator replaces the object in place keeping its id, so an id-keyed diff sees neither side. dd490 frames excluded. On the dataframe path `items` is rebound to the merged full slot before the diff, so it never compares a slot against a caller subset.

- **`perform.params.references_limit` is deliberately NOT honoured** (WC-2026-08-02-observer-references-limit-not-honoured). On the write path a capped result set is indistinguishable from "these records stopped referencing you", and the order-preserving merge removes by OMISSION — measured: tchi1/162 stores 1,023 locators against a declared limit of 200, so honouring it would destroy 823. A finite NONZERO `referencesLimit` is REFUSED outright (`observers_references_limit_refused`) rather than truncating; `0` is the uncapped sentinel most shipped configs declare (numisdata77 included) and falls through.
- **>2000-reference freeze** (`EXTERNAL_REFERENCES_FREEZE`) ported as a WRITE REFUSAL: compute and report the diff, persist NOTHING (`observers_big_result_refused`, `refusedBigResult`). Reachable — rsc387 → cult1/5 holds 4,547 referencers.
- **Concurrency**: the write phase is ONE `withTransaction` with the target row `FOR UPDATE` and the bag re-read under the lock, so two concurrent saves serialize instead of last-writer-wins; TM pair + live write commit atomically (a first-ever write also backfills a baseline TM row 60s earlier). A locked compute over 2s is logged + counted (`observers_recompute_lock_slow`). Dry run (`write:false`) is lock-free.
- **Return contract**: `before`/`after` ALWAYS describe the full-law diff, so a dry run, a degraded-seed refusal and a clean apply report the same numbers; when `skippedShrink` is set in apply mode the record actually holds `before + additions` and `seedDefects` names why.

## Safety laws (all unconditional)

- **THE FULL LAW PERSISTS, DROPS INCLUDED** (2026-08-06, WC-2026-08-06-observer-grow-only-failsafe-retired). `allowShrink` is DELETED — from the kernel options, from `ReconcileOptions`, and as the CLI flag; there is NO caller-supplied shrink switch and a static gate keeps it that way (a parameter that can mean "allow" is always one omitted argument from the unsafe value — that is what armed the 2026-08-02 wipe). The blanket grow-only fail-safe it replaced existed because the value law was known too small; the D3 closure settled that, and the guard had become the defect (a mirror that can only grow is not a mirror). Membership-based, adjudicated INSIDE the row lock (no TOCTOU), so a 1-drop+1-add swap commits BOTH halves.
- **DEGRADED-SEED SHRINK REFUSAL** — the ONE remaining withholder, and the kernel derives it. `collectExternalSeed`/`buildExternalSeed` take a per-call `defects?: string[]` sink; each never-narrow escape pushes into it (`peer_node_missing:<tipo>` / `invalid_data_from_field` / `malformed_peer_locator`) next to its counter. When `defects.length > 0 && dropped > 0` the ADDITIONS persist and the DROPS are withheld (`skippedShrink` + `seedDefects`, counter `observers_shrink_refused_degraded_seed`). Rationale: under grow-only a degraded seed cost nothing; under the full law it is the measured 247,933-locator-loss shape. Fix the ontology the defect names, then re-run the reconciler.
- **THE CLASSIFIER REFUSAL** (replaced the 2026-08-02 sub-law disarm on 2026-10-30). An ambiguous / malformed node is refused before any read (`refusedLaw`) — the closed table above. Never "unblock" a node by letting it fall to another law: law (c) on numisdata679/numisdata965 recomputes to ZERO against stored bags of 1,077 / 959 / 766 (**131,806 locators — 118,449 + 13,357 — across 4,688 records**, mostly section numisdata665). The `isPlainObject(source)` test precedes every `in` — a malformed SCALAR source is real data (oh55 string, oh90 number) and must stay the counted `component_to_search` skip, because `duplicate_record` reaches this kernel with no try/catch.
- **BOUNDED CASCADE.** An observer that PERSISTS a recompute is a save, so it re-enters propagation (`emitCascadeHop`). **Emission is NOT uniform** — only the `set_dato_external` branch gates on `outcome.wrote === true` (a refused, withheld or no-drift recompute emits NO hop); the **relay** branch emits per target UNCONDITIONALLY (emitting the hop IS the relay, it writes nothing else) and the **info** recompute emits per target unconditionally. `emitCascadeHop`'s own leaf pre-gate drops a hop into an observer with zero subscriptions before it is scheduled. The guard is a shared visited set keyed `observerTipo|kind|section_tipo|section_id` plus `MAX_CASCADE_DEPTH = 8`, threaded as a PARAMETER (never module state — module_state_tripwire). A node on its OWN chain = TRUE CYCLE (`observers_cascade_cycle_refused` — an incident, must stay 0); reached via another branch = converged diamond, benign dedup (`observers_cascade_converged_skipped`; execute-once vs re-execute-to-fixpoint is ledgered in WC-2026-08-02-observer-cascade-bounded-flag). A depth overrun is a loud counted stop naming the full chain — never a silent truncation, never a hang. The real graph is depth ≤ 2 with zero cycles.
- **Cascade hops run OUTSIDE any transaction, or on the COMMIT-ONLY lane.** `runObserverCascadeHop` ASSERTS not-in-tx and throws naming the chain (`observers_cascade_in_transaction_refused`) — `withTransaction` JOINS an ambient tx, so a hop's writes would ride a transaction it does not own, and escaping to a second connection would deadlock on the outer row locks undetectably. In-tx emission therefore defers via **`registerCommitAction` (`src/core/db/postgres.ts`) — fires ONLY on COMMIT, discarded on ROLLBACK**. **`deferPostTransaction` is a DIFFERENT, older lane that replays on ROLLBACK too — idempotent cache invalidation only, NEVER writes.** A closed commit lane (leaked continuation past `withTransaction`, S2-14) DROPS the hop loudly (`observers_cascade_hop_dropped`). `propagateToObservers` REFUSES to run inside a transaction (B6: the ledger only ever drains after COMMIT, so an in-tx call is a caller bug); after COMMIT a failure is swallowed loudly and counted `observers_propagation_failed` — the former in-tx rethrow lane and its `observers_propagation_failed_in_tx` counter are retired.
- **There is NO configuration switch.** Mirrors are STORED data, so a deploy flag would make two installs with the same ontology store different values. `DEDALO_OBSERVER_CASCADE` existed briefly and was removed the day the benchmark cleared it: one external hop p50 1.3ms / p90 3.1ms; widest records (bags to 1,189) p50 10.6ms; worst real case 4,547 referencers = 22ms; cost per entry FALLS as fan-out grows (61.8 → 5.2 ms per 100) — sub-linear.

## The obligation ledger — restores, undeletes and covered mirrors (2026-10-01)

- **A covered mirror is RECOMPUTED, never propagated.** A write that must not declare a covered observer slot — a whole-record `replace` keeps the LIVE mirror, an undelete writes the snapshot's, a component restore its past value — lists it in `selfRecompute`; the drain recomputes it from truth and **ALWAYS hops** (`recomputeMirrorAndHop(..., 'always')`), also when the recompute finds nothing to write and also on a dedup hit — the hop is that slot's own observers' only news of it. A restored mirror's past value is never propagated as edges (that was the phantom-referencer bug). Component restores reach this through `persistRestoredKeys`; the soft-cascade restore through `requestCoveredSlotRecompute` (`recompute` declaration), queued BEFORE its key writes in the same transaction.
- **ONE section census** for the covered slots — `src/core/section/record/declared_components.ts` (shared by the record wipe and the whole-section recompute): it resolves virtual sections (`getSectionRealTipo`) and crosses NESTED section nodes, so a mirror declared on the real section or under a nested node is recomputed and wiped alike.
- **Birth-column law** (`prepareBirthColumns`, create + duplicate only): a NEW record never stores a covered mirror (nor a `dato_default` for one) — it is dropped from the column set with its frames (`dropCoveredObserverUnits`), the `_hi` index re-derived, and the slot recomputed after COMMIT. A duplicate stores neither the mirror nor its frames and re-mints no frame target for them.
- **Covered-unit law**: a mirror and the dataframe frames paired to its items (`id_key → id`) move TOGETHER — replace keeps the live unit, a new birth drops it, an undelete keeps the snapshot's unit (ids kept, so each frame stays on its referencer).
- **Verbatim stamp posture**: a `birth`/`recompute` declared `verbatim` (the bulk revert's undelete; a restore whose run owns the record's stamps) puts a mark on the transaction's shared guard at ENQUEUE; a covered-slot recompute of that record then writes WITHOUT stamping it, so a revert of the revert still compares the snapshot's stamps.
- **The reconcile's index repair**: `observer_reconcile` also re-derives the `_hi` ancestor index of a mirror whose value already agrees (`reindexed`, counter `observers_index_repaired`, unstamped) — legacy, frozen and degraded-seed mirrors included; an interactive no-drift recompute never pays that chain walk under its row lock.
- **Covered = a stored law AND a `set_dato_external` edge with a resolvable shape** (`isCoveredExternalObserverNode`; `isCoveredObserverTipo` delegates). Consumers outside `observers.ts`: `record_write.ts` (`coveredSlotKeys`/`coveredSlotsOf`/`declaredCoveredSlots`, `ownDataCoveredSlots` = the copy-law slots a section declares), `duplicate_record.ts` (strips covered mains; `selfRecompute` = birth columns ∪ `ownDataCoveredSlots`, else an `observed_data` slot — a `string`-key input — never recomputed), `tool_time_machine/server/bulk_revert_records.ts` (`isRestatedEdgeSlot`: inverse + source_overwrite slots are not links; an `observed_data` slot IS, the only indexed witness of a text tag). testimmovable1000-1002 (observe edge, no `component_to_search`) are NOT covered any more.
- **The cascade hop's `removed`** set is filled from what the recompute dropped (`droppedLocators`), so a referencer that leaves also leaves a mirror OF the mirror.
- **LIMIT — drain order is not result-neutral for a mirror of a mirror.** The per-transaction guard is execute-once (WC-2026-08-02-observer-cascade-bounded-flag): when an earlier entry's cascade recomputes a second-order mirror while a LATER entry's restored mirror still holds its snapshot (a save queued before a soft-cascade restore, one transaction), it reads the phantom and the restored mirror's convergence hop is deduplicated away — that observer stays stale until `observer_reconcile`. Closing it needs a generation-aware dedup or a two-phase drain (owner decision, open).
- Gates: `obligation_ledger_native` (outcomes), `write_obligations_tripwire` (reach + exclusivity on the writer closure).

## The refresh door — the portal's update-external button (2026-10-30)

`external_refresh.ts` `maybeRefreshExternal(rqo, principal)` is called from `read_facade.ts` `routeSectionRead` (component get_data branch, after the record gate + level≥1 check, BEFORE `readComponentData`). Preconditions (miss ⇒ silent no-op): `source.build_options.get_data_external === true` (`get_dato_external` is IGNORED and counted `rqo_deprecated_get_dato_external`), `rqo.action === 'read'` on dd_core_api (dd_core_api:start can never reach it), NOT a TM read (`sqo.mode 'tm'` / TM scope ⇒ `observers_external_refresh_skipped_tm`), not temporal, component tipo ≠ section, `classifyWireSectionId` = `record`, `source.mode: external`. Then: in-tx ⇒ withheld `error`; consultation-only section ⇒ refused; `authorizeRecordAccess({mode:'read', level:1, sectionFloor:1, door: EXTERNAL_REFRESH_DOOR})` (READ LEVEL 1 — owner ruling, PHP parity: the value is derived, requester-independent); law refused / not host ⇒ withheld; then `refreshExternalMirror(tipo, section, id, actor, now)` (`observers.ts`: throws in a tx, fresh root CascadeGuard, `recomputeMirrorAndHop('on-write')`, awaited to COMMIT so the read sees it). The READ IS ALWAYS SERVED; notices `observers.refresh_refused` / `observers.refresh_withheld` (`reason`: law_refused | target_not_host | degraded_seed | frozen | busy | error). The row-lock wait is BOUNDED on this door only (`EXTERNAL_REFRESH_LOCK_TIMEOUT='3s'` as `SET LOCAL lock_timeout` first in the refresh's own transaction via `recomputeExternalRelation` `options.lockTimeout`; SQLSTATE 55P03 ⇒ withheld `busy`, `retryable:true`, nothing written; the post-COMMIT hop is NOT bounded — owner ruling: a timed-out hop leaves downstream stale). A degraded seed that WROTE is success (no notice, `done`) — `withheldReasonOf` checks `wrote` before the flags — a read-level user must never park a request-pool connection behind a long write. No-drift ⇒ zero writes, so `dd_core_api:read` stays `idempotent`. Client: `buttons.js` sends the flag once, disables the button while in flight, and clears both in `finally`; `get_buttons_by_permissions` (render_edit_component_portal.js) = full toolbar >1, external-only at 1. Tripwire rows: write_obligations B4 (`recomputeMirrorAndHop` += `refreshExternalMirror`; `refreshExternalMirror` allowed = [`maybeRefreshExternal`]).

## Diagnostic recipes

**Registry state, no repro needed** — build it against the connected DB's ontology and read the diagnostics:

```
bun -e "const m=await import('./src/core/section/record/observer_subscriptions.ts');
const i=await m.getSubscriptionRegistry(); const d=i.diagnostics;
console.log(i.edges.length,'rows |',d.mirroredServer.length,'mirrored |',d.reverseOnly.length,'reverse-only');
console.log('forwardOnly',d.forwardOnly,'deadWildcards',d.deadWildcards,'hostUnresolved',d.hostUnresolved,'cycles',d.cycles.length);
console.log('violations',m.validateSubscriptionContract(i).length); process.exit(0)"
```

Same information without a shell: GET `/api/v1/counters` → the `observers_registry` gauge, and the `observer subscription contract violation: …` boot log lines.

**"Why doesn't my edge fire?"** — (1) does the OBSERVER's `properties.observe` carry an entry whose `component_tipo` is the observed tipo (or `'all'` WITH a forward spec) and an OBJECT `server` block? `entryServerBlock` is the only predicate — `server:null` or a scalar never dispatches. (2) FIRST-match law: an earlier client-only entry for the same tipo shadows a later server one. (3) SQO-filter edges need a resolvable host section — check `observers_host_section_unresolved` and the boot log. (4) After dd_ontology surgery done OUTSIDE the engine, restart or call `clearObserverSubscriptionRegistry`.

**"Mirror stale / short"** — dry run first (the default; prints every drifted record):
`bun scripts/observer_reconcile.ts [--observer <tipo>] [--section <tipo>] [--id <n>]`, then `--apply`. It is also a CENSUS: `--json` emits one record per drifted mirror (`before`/`after`/`dropped`/`added`/`seedDefects`/`refusal`) and `--budget` adjudicates corpus drop volume against `engineering/observer_shrink_budget.json`, exiting non-zero when busted. Run the census before any `--apply`. Kernel: `observer_reconcile.ts` `reconcileObserverMirrors` — candidates from `matrix_relation_index` truth ∪ stored-mirror holders, replaying the SAME `recomputeExternalRelation`. One law, one implementation. The v6→v7 update pipeline runs it automatically (`src/core/update/engine.ts` `updateVersion`, success tail).

**"Mirror short by thousands"** — inspect the peer's `properties.config_relation.relation_type_rel`: only dd621 gets the full closure, and only for a `component_relation_related` peer. A peer whose ontology node is MISSING degrades the seed to stored-bag-only — exactly the 247,933-locator-loss shape — and counts `observers_seed_peer_node_missing`.

**Cascade suspected** — `observers_cascade_cycle_refused` must be 0 in production; `converged_skipped` is benign. Every refusal log names the full chain (`tipo@section/id -> …`).

**Standalone scripts** — the seed's model/alias resolution needs the component registry's lookup registered, so these modules dynamic-import `components/registry.ts` themselves. Keep that pattern: a static import here creates a relations↔section cycle (`RelatedGraphIO` is imported type-only for the same reason).
